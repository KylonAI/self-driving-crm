Kylon CRM · architecture overview

One CRM, fed by every system we already use, with one thread per client

Nobody types customer data into this CRM. Each source writes through one intake, each fact records where it came from, and every client's conversation lives in a single thread on its record, where people and Agents work side by side.

Account = workspace

The unit we sell to. Holds owner, Account Manager, usage series, billing status and the record thread.

Activity = anything that happened

Signup, email, meeting, form, payment, ticket. One timeline per client, each line with source and link.

Review item = a judgment call

Duplicate people, uncertain matches, merges. The system proposes, a person decides.

3 · Sync mechanism

flowchart LR
  S1[Scheduled syncs hourly / daily] --> IN[Intake API one endpoint for all writes]
  S2[Webhooks payments, bookings] --> IN
  S3[Agents in a thread notes from a call or email] --> IN
  IN --> K{Match by exact email, domain or workspace id}
  K -->|match| U[Upsert record + append activity]
  K -->|unsure| RV[Review item for a person]
  U --> PV[Store source and time for every field]
  U --> TH[Post to the client's thread when it needs attention]

One door in

Every sync, webhook and Agent writes through the same intake, so rules live in one place.

Never guess

Matching is by exact email, domain or workspace id, never by name. Anything uncertain becomes a review item.

Re-runs are safe

Writes are keyed upserts, so a sync can run again without duplicates, and each field keeps its source.

4 · One client, one thread

flowchart TB
  E[New event about a client email, booking, recap, payment, alert] --> Q1{Is this a partner?}
  Q1 -->|yes| PT[Partner's record thread]
  Q1 -->|no| Q2{Has a workspace?}
  Q2 -->|yes| AT[Workspace record thread in the CRM room]
  Q2 -->|no| PR[Prospect record thread moves into the CRM at signup]
  AT --> W[People and Agents work here: drafts, notes, follow-ups]
  W --> H[A person clicks send nothing outbound goes out alone]

Rooms are split by the kind of work (ads, outreach, CRM); threads are split by who the client is. Every card about a client, from a meeting recap to an email draft, lands in that client's one thread, so anyone can open the record and read the whole story. When a deal closes, the stage changes and the thread stays.

5 · How it maps onto Kylon

Nothing here is a separate CRM product. Every part is an ordinary Kylon building block that any workspace has.
